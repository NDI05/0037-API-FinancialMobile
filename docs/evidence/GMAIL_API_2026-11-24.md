## Perilaku yang diimplementasikan

- **OAuth dari sesi PAM aktif**: `POST /v1/gmail/connect/start` membuat `state` acak 32 byte,
  disimpan sebagai hash (sekali pakai, TTL ≤10 menit, terikat owner+PKCE verifier sealed
  AES-GCM). `GET /v1/gmail/connect/callback` memvalidasi state, menukar code, memverifikasi
  email akun, menyimpan refresh token terenkripsi, memanggil `users.watch`, menjadwalkan
  backfill, lalu redirect `pam://gmail/connected?status=success|error&reason=<safe_code>`
  — replay/expired/mismatch dijawab redirect `state_invalid`/`state_expired`, bukan 500.
- **Satu koneksi aktif per owner**: indeks unik parsial di DB; start kedua → 409,
  `reconnect:true` untuk mengganti akun (koneksi lama di-stop/di-revoke).
- **Scope minimum** `https://www.googleapis.com/auth/gmail.readonly`; status mengembalikan
  email **masked**, scope, `connected_at`, `last_sync_at`, `watch_expires_at`, `sync_state`,
  `last_error_code`. Tidak ada token/kode/email penuh di respons, DB plaintext, atau log.
- **Pub/Sub push**: `POST /v1/internal/gmail/push` memverifikasi JWT OIDC (issuer Google,
  audience `GMAIL_PUSH_AUDIENCE`, service account `GMAIL_PUSH_SERVICE_ACCOUNT`), lalu
  menyimpan event idempoten (`event_key` unik, payload sealed) dan ACK 204 — ACK dikirim
  setelah event durable; duplikat tidak menambah event. Mailbox tak dikenal di-ACK tanpa
  data (anti-enumeration). Owner **hanya** diresolusi dari hash email tersimpan.
- **Backfill 12 bulan bergulir WIB**: job per bulan kalender, bulan berjalan pertama, satu
  bulan per pass, checkpoint per batch yang sudah diakui, maks 5 halaman per tick;
  pesan di luar periode/format diabaikan; dedupe `g:g<hash email>:<messageId>` + fingerprint.
- **Delta via `history.list`**: cursor disimpan terenkripsi; `404/expired` → rescan bulan
  berjalan + cursor baru dari `profile`; retry halaman tidak kehilangan checkpoint.
- **Watch renew/stop**: renew terjadwal sebelum 24 jam; disconnect → stop watch → revoke
  token → hapus kredensial; kegagalan auth → `NEEDS_REAUTH`.
- **Privasi**: raw MIME diproses di memori dan tidak disimpan; PAN/No. Referensi tidak
  pernah disimpan/di-log; parser Livin memprioritaskan nama `Penerima`.
- **Opt-in**: `GMAIL_ENABLED=false` default; mode production divalidasi (client id/secret,
  redirect HTTPS tanpa query, topic, audience, service account).

## Temuan audit & perbaikan (putaran 2, setelah audit `9d388ae`)

Semua P1 diperbaiki bersama jembatan kategorisasi otomatis; P2 dikerjakan sebagian dan sisanya
dicatat eksplisit di bawah. Tidak ada field API baru; `sync_state` tetap memakai nilai lama.

P1 yang diperbaiki:

1. **Periode memakai tanggal transaksi, bukan tanggal email.** Email 1 Desember untuk transaksi
   30 November kini dirutekan ke bulan November dengan job impor bulan itu; transaksi di luar
   jendela retensi ditolak eksplisit `outside_retention` (bukan `outside_period` diam-diam).
   Checkpoint tetap per batch yang diakui. Tes: `TestLateEmailImportsIntoTransactionMonth`,
   `TestOutOfRetentionTransactionIsExplicitlySkipped`, plus replay tanpa duplikat.
2. **Reconnect ganti mailbox benar-benar mereset state.** Sebelum menyimpan koneksi baru,
   server mem-stop watch dan me-revoke token lama; `gmail_sync_jobs` + event push PENDING lama
   dihapus dalam transaksi store yang sama sehingga mailbox baru memulai backfill 12 bulan.
   Replay state OAuth lama ditolak dan tidak mengaktifkan koneksi lama. Tes:
   `TestReconnectToDifferentMailboxResetsSyncState`.
3. **Koeksistensi IMAP↔Gmail.** Kandidat Gmail yang identitas naturalnya (arah + nominal + waktu
   transaksi) cocok dengan baris lama ber-`source_ref` IMAP dihitung duplikat, bukan baris kedua;
   identitas kanonik Gmail tetap `g:<hash email>:<messageId>`. Keputusan gate: Gmail API menjadi
   satu-satunya jalur impor server setelah aktif, app-password perangkat dihentikan (dokumentasi
   di `docs/GMAIL_API_SETUP.md` §4.9 dan kontrak §7). Tes: `TestGmailBackfillMergesExistingIMAPRow`.

P2 yang diperbaiki:

- **Race job DELTA**: unique index parsial `idx_gmail_sync_jobs_open_delta` (migrasi 018) +
  `INSERT ... ON CONFLICT DO NOTHING`; tes `TestEnsureDeltaJobIsSingleFlight`.
- **`recoverHistory` mengabaikan batas halaman**: kini memakai checkpoint page token dan hanya
  menyimpan cursor baru setelah seluruh rescan selesai; job tetap terbuka bila kena bound.
  Tes: `TestRecoveryResumesFromCheckpoint`.
- **Event push FAILED tidak pernah di-retry**: query mengambil `FAILED` dengan `attempts < 3`;
  event diproses setelah job delta durable. Tes tidak terpisah (tercakup jalur push).
- **Token revoked/scope hilang di-retry tiap tick**: `needs_reauth` menghentikan sinkronisasi
  otomatis sampai reconnect; gangguan provider sementara di-retry dengan backoff 10 menit.
  `isTransientProviderError` yang mati dihapus. Tes: `TestNeedsReauthStopsAutomaticRetry`.
- **`GMAIL_SCOPE` vs hardcode callback**: verifikasi scope callback memakai `Settings.Scope`.
- **Klaim "Sinkronkan sekarang" di README**: dihapus; tidak ada endpoint manual.
- **Batch key saat resume**: kunci batch kini menyertakan fingerprint page token sehingga
  halaman yang di-resume tidak memicu `ErrIdempotencyConflict`.

P2 yang belum diperbaiki (dicatat, bukan blocker gate):

- `404` dari `messages.get` masih diperlakukan `history_expired` di jalur delta (bukan di
  backfill); pembedaan kode error per endpoint belum dipisah.
- Counter `seen/imported/duplicate/skipped` pada job DELTA normal memakai nilai checkpoint
  terakhir, bukan akumulasi setelah setiap batch (hanya observability).
- `ConsumeGmailOAuthState` belum memeriksa `RowsAffected` saat menandai `consumed_at`.
- Alasan skip `import_skipped` sudah berupa kode aman; belum ada pemetaan ulang tambahan.
